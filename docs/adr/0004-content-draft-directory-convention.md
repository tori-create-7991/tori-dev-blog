# 0004. コンテンツの下書きはコレクション直下の `drafts/` サブディレクトリに置く

Status: Accepted

## Context

`blog-post-writer`（00_my_env の執筆スキル）や今後の feed 投稿パイプラインが
自動生成する下書きと、公開済みコンテンツを分離したい。下書きは公開前に
人間のレビュー（秘匿情報の混入チェック等）を経る必要があり、誤って
サイトに公開されない状態で git 管理下に置ける場所が要る。

## Decision

各コレクションのソースディレクトリ直下に `drafts/` サブディレクトリを切り、
下書きはそこに置く:

- `content/posts/drafts/*.md`
- `content/feed/drafts/*.md`

`content.config.ts` の `source` グロブ（例: `posts/*.md`）は `*` が
パス区切り文字をまたがないため、`drafts/` 配下のファイルは追加のフィルタ
コードなしで自動的にコレクションから除外される（ページ一覧・タグ/カテゴリ・
RSS・sitemap のいずれにも出現しない）。この挙動は `nuxt build` で
`posts/drafts/*.md` に置いたファイルがプリレンダー出力・出力バンドルの
どこにも含まれないことを確認済み。

公開する際は該当ファイルを `drafts/` から親ディレクトリへ `git mv` する
だけでよい（frontmatter や送信元コードの変更は不要）。

## Consequences

**良い面:**
- 公開判定のためのフィルタリングロジックがページ・API ルートのどこにも
  不要（`content.config.ts` のスキーマも無変更）
- 「公開する」操作が `git mv` 一発で完結し、レビュー後の作業が単純
- 下書きも git 管理下にあるため差分・履歴が残る

**悪い面:**
- 下書きと公開を分けるのがディレクトリ位置のみのため、`git mv` を忘れると
  永久に下書きのまま残る（ビルド失敗など気づく仕組みはない）
- コレクションの `source` グロブを将来 `posts/**/*.md` のような再帰パターンに
  変更すると、この分離が暗黙に壊れる（変更時は `drafts/` 配下が
  意図せず公開されないか確認が必要）
- `content.config.ts` の汎用 `content` コレクション（`source: '**/*.md'`）は
  現状どのページからも `queryCollection('content')` されておらず未使用だが、
  将来サイト内検索等で使い始めると `**/*.md` は `drafts/` 配下も再帰的に
  拾ってしまう（`posts`/`feed` コレクションの `posts/*.md` とは異なりパス
  区切りをまたぐ）。使い始める際はこの分離が効かないことを踏まえる
